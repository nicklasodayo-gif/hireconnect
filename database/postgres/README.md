# PostgreSQL migration (not yet the running database)

The application currently runs on SQLite via `node:sqlite`
(`server/src/db.ts`) — genuinely tested, 27/27 tests passing. This
directory is the **prepared, ready-to-use migration path** to Postgres,
per Phase 24, built so the switch is mechanical rather than a rewrite —
but it has **not been run against a live Postgres server**, because this
sandbox has neither a Postgres binary nor npm registry access to install
`pg`. Treat it as reviewed-and-ready, not "confirmed working against a
real database."

## What's here

- `migrations/0001_init.sql` — the full schema, translated from
  `docs/SCHEMA.sql` (SQLite) to native Postgres types: `BIGSERIAL` instead
  of SQLite's rowid alias, `TIMESTAMPTZ` instead of TEXT timestamps,
  native `BOOLEAN` instead of 0/1 integers, `JSONB` for JSON columns, and
  a full-text search index on job title/description (a genuine upgrade
  SQLite's plain `LIKE` scan doesn't have).
- `seed.sql` — a small illustrative seed (1 admin, 1 employer + company, 1
  candidate, 1 job) using **genuinely computed password hashes** — these
  were generated by actually running `server/src/auth.ts`'s
  `hashPassword()` and confirmed to round-trip correctly with
  `verifyPassword()` before being pasted in, not placeholders.

## Running it

```bash
createdb hireconnect
psql "$DATABASE_URL" -f database/postgres/migrations/0001_init.sql
psql "$DATABASE_URL" -f database/postgres/seed.sql
```

Both are plain SQL, runnable with `psql` alone — no Node/`pg` package
required just to stand up the schema and a small demo dataset.

## To actually switch the running app to Postgres

1. `npm install pg` in `server/`.
2. Replace `server/src/db.ts`'s `DatabaseSync` with a `pg.Pool`, and change
   `server/src/app.ts`'s `db.prepare(sql).get/all/run(...)` calls to
   `pool.query(sql, params)` — the SQL strings themselves need minimal
   change (mostly `?` → `$1, $2, ...` placeholders).
3. Port `server/src/seed.ts` (the full 10-company/22-job/22-candidate
   Kenyan dataset, currently SQLite-only) to use the same `pg.Pool` —
   `hashPassword()` and `calculateMatch()` are already plain functions
   with no database dependency, so they carry over unchanged.
4. Re-run the existing test suite (`server/tests/*.test.ts`) against the
   Postgres-backed server — the tests exercise the HTTP API, not the
   database driver directly, so they should need no changes themselves.

This order (schema → seed → app switch → re-test) keeps the app
runnable at every step, per Rule 11.
